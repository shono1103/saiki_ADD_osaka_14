# catalog/ — デッキ閲覧

台本を書くとき・本番デッキを組むときに**眺めて選ぶ**ための参照用ディレクトリです。
ここのファイルは直接編集せず、`deck/` にコピーしてから手を入れます。

## 閲覧する

```bash
pnpm run view              # 一覧を表示
pnpm run view patterns     # 1 画面パターン集
pnpm run view tech-talk    # 技術解説のデッキ構成
```

ブラウザが開きます。<kbd>o</kbd> で全スライドの一覧表示、<kbd>→</kbd> で次へ進みます。

## 1 画面パターン集 — `patterns.md`

## デッキ構成 — 用途別に 10 種

デッキ全体の「話の順番」の型です。各スライドのスピーカーノートに、
**そこで話す内容の指針と時間配分**が書いてあります。

| 名前 | 用途 |
| --- | --- |
| `lightning-talk` | LT（5 分）。1 枚 1 メッセージでテンポよく |
| `tech-talk` | 技術解説・勉強会（20〜30 分）。章立てで迷子にさせない |
| `proposal` | 企画・提案。結論から入り、判断してほしいことで締める |
| `project-report` | プロジェクト進捗報告。状態を色で示し、相談事項を明示 |
| `design-review` | 設計レビュー・ADR。代替案の比較と採用理由を残す |
| `postmortem` | 障害報告。Blameless で事実 → 原因 → 再発防止 |
| `retrospective` | ふりかえり（KPT）。進行の台本つき |
| `workshop` | ハンズオン・研修。チェックポイントで足並みを揃える |
| `product-pitch` | 製品・サービス紹介。相手の課題から入る |
| `research` | 研究発表・調査報告。RQ と結果を 1 対 1 で対応させる |

本番に流し込むには:

```bash
pnpm run new tech-talk          # deck/slides.md が無ければそのままコピー
pnpm run new tech-talk --force  # 既存をバックアップして上書き
```
